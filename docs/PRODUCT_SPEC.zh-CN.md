# 产品规格

## 问题

开发者需要可复现地回答一个窄问题：MCP stdio 服务启动后，初始化是否成功，输入
关闭后是否退出？全局操作系统进程检查会暴露大量无关状态，也增加误杀无关进程的风险。

## 契约

MCP Process Guard 不通过 shell，只启动一个明确命令并创建隔离的子进程组；它可选
执行换行分隔的 MCP `initialize` 请求和 `notifications/initialized` 通知，然后关闭
stdin 并等待有限宽限期。超时
后只清理所属进程组。根进程先退出时，工具仍会查询 Unix 进程组或 Windows Job
Object 中的所属后代。报告包含结果、握手状态、耗时、退出码、后代检测和结构化清理证明。

在 Unix 上，`cleanup: succeeded` 表示面向进程组的终止信号已被接受，且直接子进程在
清理期限内被回收。已终止的后代可能短暂保留为不再运行的僵尸进程，等待新父进程回收；
本工具不会为此扫描全机或检查无关父进程，并将这种有界不确定性报告为
`cleanup: unverified`，而不是成功。Windows 还要求 Job Object 活跃进程计数归零。

## 非目标

- 常驻运行或充当通用进程清理器。
- 发现、扫描或终止无关进程。
- 转发任意 MCP 流量或验证完整协议一致性。
- 采集载荷、日志、参数或环境变量值。
- 隔离不可信可执行文件。

## 验收条件

- 区分正常退出、非零退出、握手失败和超时。
- 等待有上限，超时清理只针对所属进程组。
- 人类与 JSON 输出均不回显命令或参数。
- 握手帧和所有等待均具有经过校验的上限。
- CI 覆盖 Linux、macOS 与 Windows 构建，并明确记录平台限制。

在 Unix 上，主动通过 `setsid` 创建新会话的后代会离开所属进程组，本工具无法再归属
或清理它。Windows 使用带 `KILL_ON_JOB_CLOSE` 的私有 Job Object 进行归属与计数。
